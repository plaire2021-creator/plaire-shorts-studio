# 플레르 제품 숏츠 자동 제작

사용자는 **중간 확인 없이 끝까지 자동**으로 만들기를 원한다. 장면안·자막안을 보여주고 승인을 기다리지 말 것. 다만 아래 "멈추는 경우"에 해당하면 그때만 묻는다.

이 스킬은 `plaire-shorts-studio` 플러그인에 들어 있다. 스킬 폴더(이 파일이 있는 곳, 로드될 때 "Base directory"로 표시됨)를 `<스킬>`이라 하면 플러그인 루트는 `<스킬>\..\..` 이다.
- 엔진(Remotion): `<플러그인>\engine` — node_modules가 없으면 CLI가 처음 실행 때 자동 설치(1~2분)
- CLI: `python "<플러그인>\scripts\shorts.py" <명령>` (아래 `shorts.py`로 표기)
- 설정 예시(승인된 v3, 모듈 3단 서랍장): `<플러그인>\examples\shorts_example.json`
- 필요한 것: Python(numpy, Pillow), Node.js 18+
- 결과물 위치: `<제품폴더>\숏츠_영상\`

## 입력

사용자가 주는 것: 제품 폴더 경로(보통 `D:\주혁\제품 상세페이지 제작\<제품명>`). 폴더 안에 보통
- `사진자료\` 촬영 원본(가로 5520×3680, 세로 5520×8280 섞임) + 컬러 라인업 등 기타 이미지
- `분할_JPG\` 상세페이지를 잘라 둔 이미지 → 자막 문구·사이즈·소재·인증·컬러명의 출처
- `상세페이지_등록` 스튜디오에서 따로 올린 상세페이지 이미지(올린 순서대로 상세_001.jpg…). `분할_JPG`와 같은 용도
- `상품명_키워드_선정근거.xlsx`가 있으면 첫 시트의 '최종 상품명'을 엔딩 상품명으로 쓴다(상세페이지 스펙표 이름과 다를 수 있음 — 엑셀 우선)

## 작업 순서

### 1. 자료 훑기
```
python shorts.py sheets "<제품폴더>"
```
`<제품폴더>\숏츠_영상\_시트\`에 사진 시트(파일명·크기 표기)와 상세페이지 시트가 생긴다. **전부 Read로 본다.** 상세페이지 시트에서 헤드카피·스펙(W×D×H)·컬러 목록·소재·인증(KC, E1 등)·기능(볼레일, 수평조절발 등)을 뽑는다.

### 2. 장면 구성 (기본 6장면, 합계 435~480프레임 = 14.5~16초)
120BPM에서 1박=15프레임. **모든 장면 길이는 15의 배수** (전환이 박자에 맞음).

| # | type | 길이 | 내용 |
|---|---|---|---|
| 1 | `pan` | 75 | 컬러 라인업 사진을 옆으로 훑는 오프닝. 손님 상황 훅 자막 |
| 2 | `photo` | 75 | 무드 클로즈업(소품·조명이 있는 컷) — 감성/공간 이점 |
| 3 | `photo` | 75 | 수납·기능 컷(서랍 열림 등) |
| 4 | `photo` | 60 | 소재·프레임·디테일 클로즈업 |
| 5 | `photo` | 60 | 신뢰 포인트(국내제작·인증·자재) — 다른 컬러 컷 사용 |
| 6 | `end` | 120 | 전신이 보이는 공간 컷 + 브랜드·상품명·사이즈·컬러칩·CTA |

- **라인업 사진이 없을 때**(단일 컬러이거나 모든 컬러가 한 줄로 선 사진이 없음): 1번을 `photo`(zoom `[1.15, 1.02]`)로 바꾼다. 첫 장면 photo는 자막이 0프레임부터 크게 뜨는 후킹 모드로 자동 렌더된다. 컬러가 여럿이면 5번 뒤에 `colors`(컬러당 15~18프레임, 각 컬러 같은 구도 컷) 장면을 넣는다. **컬러를 0.3초씩 휙휙 넘기는 `flip`은 쓰지 말 것** — "너무 빨라서 보기 어렵다"고 거절됨.
- 컷 고르기: 제품이 크게, 선명하게 보이는 컷. **사람이 나오는 컷 금지.** 같은 컬러만 계속 쓰지 말고 2~5번에 여러 컬러를 섞는다. 세로 원본은 9:16에 잘 맞고, 가로 원본은 제품 중심(cx)을 잘 잡아야 한다.

### 3. 자막 카피 규칙
- **손님 상황 → 해결** 흐름. 사양 나열식 금지. 1번은 공간의 불편/허전함을 짚는 문장(예: "소파 옆 빈자리, / **컬러 하나**로 채워요").
- 장면당 메인 2줄, **한 줄 11자 이하**(공백 포함, `**` 제외). 보조자막(sub) 20자 이하, 필요할 때만.
- 줄마다 핵심 단어 1개를 `**단어**`로 감싸 형광펜 강조(장면당 1~2개).
- 문구 근거는 상세페이지에 있는 내용만. 가격·배송·할인 등 없는 정보는 쓰지 않는다.
- 엔딩 `title`은 상품명을 2줄로(예: "미드센츄리" / "모듈 3단 서랍장"), `spec`은 `W600 · D400 · H640 mm` 형식, `cta`는 기본 `검색창에 **플레르가구**`.
- `brand`는 `PLAIRE 플레르가구`.

### 4. 컬러 칩 색상
사진에서 제품 면의 실제 색을 고른다(밝은 쪽~그늘의 중간). **"화이트"는 항상 `#f4f4f2`** (사진 평균의 누런 베이지 금지). 참고값: 옐로우 `#e6c02f`, 딥그린 `#2f4a42`, 네이비 `#2f3549`, 블랙 `#1e1e1e`.

### 5. 라인업 오프닝 수치 (`pan` 장면)
```
python shorts.py lineup "<라인업 이미지>" --out "<제품폴더>\숏츠_영상\_시트"
```
`lineup_눈금.jpg`를 Read로 보고 각 제품의 가로 중심 x(0~1)와, 제품 몸체의 세로 범위 y0~y1(이미지 높이 대비 비율)을 읽는다. 출력된 aspect도 그대로 쓴다.
- `height` = 560 / (y1 − y0) (반올림). 단, 제품 한 대 폭이 화면 절반(약 520px)을 넘지 않게
- `top` = 760 − y0 × height (제품 윗면이 y≈760, 아랫면이 1320 이하로 와야 쇼츠 제목줄에 안 가림)
- `bandTop` = 520 (컬러 칩 줄 위치)
- `items`는 사진 속 왼쪽→오른쪽 순서대로 `{name, hex, x}`
- 사진 파일은 `copy`로 public에 복사(`"lineup.jpg": "<원본 파일명>"`)

### 6. shorts.json 작성
`<제품폴더>\숏츠_영상\shorts.json`을 `examples\shorts_example.json` 구조 그대로 작성한다.
- `source_dir`: `"../사진자료"` (json 기준 상대경로), `output`: `"<상품명 짧게>_숏츠.mp4"`
- `crops`: `{이름: {file, cx, cy, zoom}}` — 원본을 9:16로 자를 중심(0~1). 가로 원본은 cx가 핵심, 세로 원본은 cy도 조정. zoom>1이면 더 타이트하게
- 장면의 `src`는 `"<crops 이름>.jpg"`
- `music`: `{"style": "jazz", "bpm": 120}` (승인된 재즈 하우스. 가벼운 pop 스타일은 거절됨)

### 7. 제작 + 자가 검수 (자동 반복)
```
python shorts.py prepare "<shorts.json>"     → _검수\크롭_미리보기.jpg 를 Read
python shorts.py guides  "<shorts.json>"     → _검수\안전영역_검수.jpg 를 Read
```
검수 기준 — 하나라도 걸리면 json을 고치고 해당 단계를 다시 돌린다(사용자에게 묻지 않음):
- 크롭: 제품이 잘리거나 화면 구석에 몰리지 않았나, 사람이 보이지 않나
- 안전영역: 자막 박스·컬러칩·CTA가 빨간 영역(위 150px, 아래 600px, 오른쪽 150px)에 겹치지 않나. 엔딩·pan 장면의 제품이 아래 빨간 영역에 크게 가리지 않나
- 자막이 박스 밖으로 넘치지 않나(넘치면 줄을 줄이거나 나눔), 0초 프레임에 자막이 보이나
- 스크립트가 찍는 "주의:" 경고(글자 수, 박자 어긋남)를 해결

통과하면:
```
python shorts.py render "<shorts.json>"
```
출력의 video/audio 길이가 같고 오디오 rms가 0.1 이상인지 확인.

render는 원본 mp4와 함께 `<이름>_업로드용.mp4`(9MB 이하, 브라우저 자동 업로드는 파일 1개 10MB 제한)를 만든다.

### 8. 제목·설명글 작성 + 전달
1. **제목 25자 이내**(공백 포함) 1개, **설명글 150자 이내**(해시태그 포함) 1개를 확정한다. 글자 수는 반드시 python `len()`으로 센다. 타 브랜드명(USM 등)은 해시태그에 넣지 않는다.

   **카피는 '스크롤을 멈추게 하는' 후킹이 목적이다. 제품 설명문이 아니다.**
   - 타깃: 화이트·우드 톤 인테리어를 고민하는 30~40대(신혼·이사 준비·아이 있는 집). 이 사람이 피드를 넘기다 "어? 우리 집 얘기네" 하고 멈출 문장을 쓴다.
   - 제목은 아래 후킹 유형 중 하나로 쓴다. 앞 10자 안에 훅(불편·의외성·결과)이 와야 한다.
     - 결과/변화: "TV장 하나 바꿨는데 거실이 호텔 됐어요"
     - 의외성/반전: "칼로 긁어도 멀쩡한 거실장, 실화예요?"
     - 원인 지목: "화이트 거실이 밋밋하다면 TV장 탓이에요"
     - 공감 불편: "식탁 위 물건, 매일 치우기 지치셨죠?"
     - 욕구 자극: "거실 사진 자꾸 찍게 되는 TV장"
   - 금지: 사양 나열("2600mm 세라믹 거실장"), 뜻이 흐린 감성어("한 방울", "하나로", "완성"만 덩그러니), 제품명만 있는 제목, 느낌표 남발.
   - **후보를 5개 쓰고** 스스로 점수를 매긴다(훅 세기·구체성·타깃 공감 각 5점). 가장 높은 것을 고르고 나머지는 result.json `title_options`에 남긴다.
   - 설명글 구조(4줄):
     1줄: 제목이 던진 궁금증·불편에 답하는 한 문장(손님 말투, "~했다면/~였어요")
     2줄: 가장 강한 근거 2개를 손님 이득으로("칼로 긁어도 자국 없는 상판" O / "통세라믹 상판" X)
     3줄: 생활 장면 하나(셋톱박스·멀티탭 쏙, 아이 있어도 안심 등)
     4줄: 해시태그 4~6개 — 품목 키워드 + 인테리어 키워드(#화이트인테리어 등) + #플레르가구. 키워드는 상품명 키워드 엑셀의 조회수 높은 단어 우선
   - 자막 카피와 같은 문장을 그대로 반복하지 않는다(영상과 글이 서로 보완하게).
2. `<제품폴더>\숏츠_영상\업로드_정보.txt`에 저장: 제목 / 설명글 / 영상 경로(원본·업로드용) / 컬러 #hex
3. `SendUserFile`로 mp4 전달(display render) + 장면 표 + 제목·설명글(각 글자 수 표기) + 컬러별 #hex(카페24 옵션 색상 설정용)
4. 사람이 확인해야 할 것: 음악은 직접 들어봐야 함, 라인업 사진이 AI 생성 이미지면 그 사실

### 9. SNS 업로드 (게시 전 한 번만 확인)
게시는 공개 콘텐츠 발행이라 **사용자의 명시적 승인 없이는 절대 게시하지 않는다.** 8번 전달과 같은 턴에 AskUserQuestion(multiSelect)으로 묻는다: "이 영상과 제목·설명글로 어디에 게시할까요?" 선택지: 유튜브 쇼츠 / 틱톡 / 인스타그램 릴스 / 지금은 안 함. 선택된 곳만, 선택한 그 영상·문구 그대로 올린다(문구를 바꿨다면 다시 묻는다).

업로드는 **Claude in Chrome**(사용자 크롬, 로그인 상태 사용)으로 한다. 먼저 `anthropic-skills:chrome-browser` 스킬을 읽고 도구를 한 번에 로드. 파일은 `file_upload` 도구로 `_업로드용.mp4`를 넣는다(파일 input의 ref를 find/read_page로 찾고, 업로드 버튼을 클릭해 네이티브 파일창을 열지 말 것). 경로가 거부되면(제품 폴더는 보통 세션 접근 범위 밖) 영상 파일을 현재 작업 폴더의 `_숏츠업로드\` 에 영문 파일명으로 복사해서 다시 시도.

**유튜브 쇼츠** — `https://studio.youtube.com` → 만들기 → 동영상 업로드 → 파일 input에 업로드
- 제목: 확정 제목(25자) / 설명: 설명글
- 시청자층: "아니요, 아동용이 아닙니다"
- 다음 ×3 → 공개 상태 "공개" → 게시 → 표시되는 영상 링크(youtube.com/shorts/…)를 기록

**틱톡** — `https://www.tiktok.com/tiktokstudio/upload` → 파일 input에 업로드
- 설명란: 제목 + 줄바꿈 + 설명글(해시태그 포함, 4000자 제한 내)
- 공개 범위 "모든 사람" → 게시 → 콘텐츠 목록에서 링크 기록
- (대안: Higgsfield MCP의 tiktok_* 도구는 계정 연결과 Higgsfield 호스팅 업로드가 필요해 기본 경로로 쓰지 않음)

**인스타그램 릴스** — `https://www.instagram.com` → 새로운 게시물(만들기) → 파일 input에 업로드
- 자르기: 원본(9:16) 유지 → 다음 → 다음
- 캡션: 제목 + 줄바꿈 + 설명글 → 공유 → 완료 표시 확인

**공개 범위는 항상 전체공개**(사용자 지시, 2026-10-21): 유튜브 "공개", 틱톡 "지금·모두", 인스타그램 피드 공유. 인스타그램 공유 설정의 페이스북 동시 공유는 끈다(요청 없음).

공통: 각 단계마다 스크린샷으로 확인하고, 게시 직전 화면(제목·설명·공개 범위)을 확인한 뒤 게시 버튼을 누른다. 로그인 화면이 나오면 멈추고 사용자에게 로그인을 요청(비밀번호 입력 금지). 같은 동작이 2~3번 실패하면 멈추고 보고. 끝나면 만든 탭을 닫고, `업로드_정보.txt`에 플랫폼별 게시 링크·시각을 추가해 사용자에게 링크를 전달한다.

**네이버 클립 / 네이버 쇼핑 숏클립은 자동 업로드 불가** — Claude in Chrome과 내장 브라우저 모두 naver.com 계열(clip.naver.com, sell.smartstore.naver.com)이 보안 정책상 차단되어 있다. 이 두 곳은 사용자가 직접 올리도록 안내만 한다:
- 네이버 클립: PC 클립 크리에이터 웹(클립 프로필 필요) 또는 네이버 앱에서 `_업로드용.mp4` 또는 원본 업로드, 제목·설명글은 `업로드_정보.txt`에서 복사
- 쇼핑 숏클립: 스마트스토어센터에서 해당 상품에 연결해 등록(상품 연결이 핵심)

## 멈추는 경우 (이때만 질문)
- 제품 폴더에 쓸 만한 제품 사진이 거의 없음(5장 미만)
- 상세페이지·엑셀 어디에도 상품명이 없음
- 렌더가 같은 오류로 두 번 실패

## 엔진 참고
- 장면 타입: `pan`, `photo`, `colors`, `end` (그리고 쓰지 않는 `flip`). 정의는 `<플러그인>\engine\src\Shorts.tsx`
- 렌더 결과물 외에 `숏츠_영상\public\`(크롭·음원), `_검수\`, `_시트\`가 생긴다. 지우지 말 것(재렌더용)
- BGM은 `<플러그인>\scripts\make_bgm.py`로 합성한 자체 음원이라 저작권 문제 없음. 장면 전환 직전 whoosh, 엔딩 직전 드럼 필·임팩트·로즈 코드가 자동으로 박자에 맞춰 들어간다
- 음악·스타일을 사용자가 바꿔 달라고 하면 `music.style`, `bgmVolume`, `accent`(형광펜 색, 기본 `#f2c94c`)로 조정

## 스튜디오 모드 (숏츠 스튜디오 사이트에서 호출될 때)
프롬프트에 "스튜디오 모드"가 있으면 숏츠 스튜디오(로컬 사이트)가 백그라운드로 실행한 것이다. 사람이 대화를 보고 있지 않다.
- 1~7단계(제작·자가 검수·렌더)는 똑같이 하되 **질문하지 않는다**. "멈추는 경우"에 해당하면 `result.json`에 `{"error": "<이유>"}`만 쓰고 끝낸다.
- 8단계의 SendUserFile·표 출력, **9단계 업로드는 하지 않는다**(업로드는 사이트가 공식 API로 한다).
- 대신 `<제품폴더>\숏츠_영상\result.json`을 UTF-8로 쓴다:
```json
{
  "video": "<원본 mp4 절대경로>",
  "upload_video": "<_업로드용.mp4 절대경로>",
  "title": "<25자 이내>",
  "description": "<150자 이내, 해시태그 포함>",
  "title_options": ["<탈락한 제목 후보 4개>"],
  "colors": [{"name": "화이트", "hex": "#f4f4f2"}],
  "scenes": [{"time": "0~2.5초", "scene": "컬러 라인업", "caption": "소파 옆 빈자리, 컬러 하나로 채워요"}],
  "notes": ["라인업 사진은 AI 생성 이미지"]
}
```
- 프롬프트에 "수정 요청"이 있으면 기존 `shorts.json`을 고쳐 다시 렌더하고 result.json을 갱신한다.

## 문구 모드 (이미 만든 영상을 올릴 때 — 숏츠 스튜디오 '제작된 숏츠 업로드')
프롬프트에 "문구 모드"가 있으면 영상은 사장님이 이미 만든 것이다. **영상을 새로 만들거나 고치지 않는다.** 제목·설명글만 쓴다. 질문하지 않는다.
1. `python <플러그인>\scripts\shorts.py intake "<올라온 영상>" --out "<제품폴더>\숏츠_영상"` → 업로드용 mp4(H.264·AAC로 맞춤)와 `_장면_프레임.jpg`(장면 9컷)가 생긴다. 출력 JSON의 `upload_video`를 기억한다.
2. `_장면_프레임.jpg`를 Read로 보고 영상에 나오는 제품·공간·자막을 파악한다. `<제품폴더>\상세페이지_등록\`이 있으면 `shorts.py sheets "<제품폴더>"`로 상세페이지 시트를 만들어 함께 본다(스펙·소재·기능 근거).
3. 8단계 규칙 그대로 제목(25자)·설명글(150자)을 쓴다 — 후킹 유형, 후보 5개 채점, 설명글 4줄 구조. 근거는 영상 화면과 상세페이지에 있는 것만. 영상 자막과 같은 문장을 반복하지 않는다.
4. `<제품폴더>\숏츠_영상\result.json`을 UTF-8로 쓴다:
```json
{
  "video": "<upload_video 절대경로>",
  "upload_video": "<upload_video 절대경로>",
  "title": "<25자 이내>",
  "description": "<150자 이내, 해시태그 포함>",
  "title_options": ["<탈락한 제목 후보 4개>"],
  "scenes": [],
  "notes": ["원본이 HEVC여서 H.264로 변환함"]
}
```
- 프롬프트에 "문구 수정 요청"이 있으면 영상은 건드리지 말고 그 요청대로 제목·설명글만 다시 써서 result.json을 갱신한다(intake는 업로드용 mp4가 이미 있으면 다시 하지 않아도 됨).
- intake가 실패하면(영상 파일이 깨짐 등) `{"error": "<이유>"}`만 쓰고 끝낸다.
