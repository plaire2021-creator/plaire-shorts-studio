# 리뷰 답글 작성 (플레르가구 · 가즈다가구)

리뷰 엑셀 하나를 받아서 → 리뷰·사진을 전부 확인하고 → 답글을 쓰고 → 한 페이지로 정리해 아티팩트로 올린다.
리뷰 캡처 이미지 한 장만 받으면 페이지 없이 답글을 코드블록으로 바로 준다(규칙은 똑같이 적용).

## 0. 브랜드부터 확인

엑셀에 브랜드 열이 없다. **사용자가 브랜드를 말하지 않았으면 먼저 물어본다.** 하단 고객센터 번호가 브랜드마다 달라서, 틀리면 고객이 엉뚱한 곳으로 연락한다.

| | 플레르가구 | 가즈다가구 |
|---|---|---|
| 마지막 인사 | `저희 플레르가구를 믿고 구매해주셔서 감사합니다!` | `저희 가즈다가구를 믿고 구매해주셔서 감사합니다!` |
| 하단 블록 | `[플레르가구]`<br>`고객센터 : 010-8981-0097`<br>`인스타 : @_plaire_official` | `[가즈다가구]`<br>`고객센터 : 010-3099-0097`<br>`인스타 : @gazda_furniture` |
| 자주 나오는 상품 | 사이드테이블 600, 샤프·슈리·솔리브 의자, 리브랑·피네·블랑드·서핑보드 테이블, 까펠로, 폴딩베드, 템바보드 거실장 | 벤도·와와·에딕스·알파 회의테이블, 에스페라·스댕스댕·라비스 대기의자, 바로스·올탐 사이드테이블, 포그니 좌식의자, 디딤 사다리, 라이즈 |

브랜드에 따라 달라지는 건 위 두 값뿐이다. 말투·규칙은 완전히 같다.

## 1. 엑셀 풀기

작업 폴더는 세션 scratchpad 아래 새 폴더(예: `<scratchpad>\rv_YYYYMMDD_brand`). 없으면 `%TEMP%\review-reply\...`.

```
powershell -NoProfile -ExecutionPolicy Bypass -File "<스킬폴더>\scripts\extract_reviews.ps1" -Xlsx "<엑셀경로>" -WorkDir "<작업폴더>"
```

`reviews.txt`를 Read 로 전부 읽는다. 열 의미:
- **B** 상품명(옵션 포함) · **C** `일반` / `한달사용` · **D** 별점 · **E** 사진 URL · **F** 리뷰 · **H** 작성자 · **I** 등록일
- **M** = C가 `한달사용`일 때 **그 고객의 첫 리뷰**. 한 달 후기 답글은 "처음엔 ~라고 하셨는데, 한 달 지나서도~" 흐름으로 잇는다.
- 같은 작성자가 여러 건 남겼으면(같은 문장 복붙 포함) 답글은 **서로 다르게** 쓴다.

## 2. 사진은 전부 직접 본다 (생략 금지)

```
powershell -NoProfile -ExecutionPolicy Bypass -File "<스킬폴더>\scripts\fetch_photos.ps1" -WorkDir "<작업폴더>"
```

`img\small\rowN.jpg`를 **한 장도 빼지 않고** Read 로 연다(병렬로 여러 장씩). 확인할 것:
- 무엇이 보이는지(공간·함께 놓인 것·사용 장면) → 답글에서 사진 얘기는 **보이는 것만** 쓴다.
- **옵션 색과 사진 속 색이 다르면** 답글에서 색 이름을 쓰지 않고, 카드 메모에 적는다.
- 스크립트가 `같은 사진`이라고 표시한 행은 한 고객이 같은 사진을 여러 리뷰에 올린 것 → 사진 속 제품을 단정하지 말 것.
- 박스·근접샷처럼 제품이 잘 안 보이면 사진 얘기를 짧게 하거나 뺀다.

## 3. 답글 쓰기 규칙

### 3-1. 최우선: 사실 · 예의
- **리뷰와 사진에 없는 내용은 지어내지 않는다.** 소재·마감·설계 의도·사이즈 같은 제품 사양도 상품명이나 리뷰에 없으면 쓰지 않는다(예: 오일 마감, 세라믹 여부, "이렇게 설계했다").
- 고객 말을 **반대로 뒤집지 않는다**(불만을 칭찬으로 둔갑 금지).
- **고객을 평가하지 않는다**: 안목·센스·잘 고르셨네요·탁월한/현명한 선택·효도·효자 금지.
- **고객 감정을 짐작해 단정하지 않는다**: `아쉬우셨겠어요` `좋으셨겠어요` `속상하셨겠어요` `걱정하셨을 텐데` 같은 `~셨겠어요 / ~셨을 텐데` 꼴 금지(예의 없어 보인다). 고객이 직접 쓴 감정을 받아주거나, 저희 쪽 마음(`다행이에요`, `죄송해요`, `감사해요`)으로 말한다.
- **큰따옴표(") 금지.** 고객 말은 풀어서 받는다.
- 건강·의료 얘기(허리, 디스크 등)가 나와도 **효과를 말하지 않는다**.
- 안전에 관한 칭찬(테이블에 올라가도 튼튼 등)은 고맙게 받되 `올라가실 땐 꼭 조심해주세요` 한 줄.
- 아이디 앞자리만 같은 다른 날 리뷰를 같은 고객이라고 답글에 쓰지 않는다(메모에만).

### 3-2. 말투 (담당자 실제 문체)
- 30대 CS 담당자가 손님에게 말하듯 **자연스러운 구어체**. 소리 내 읽었을 때 어색하면 고친다.
- **한 줄에 한 문장.** 본문 4~7줄(긴 리뷰는 9줄까지).
- 문장 끝은 마침표 대신 `!` `~` `~!` 위주(마침표는 답글당 1~2개까지).
- 단정 대신 `~것 같아요`를 가끔 섞는다.
- `ㅎㅎ`는 답글당 1~3회. `ㅜㅜ`는 사과뿐 아니라 감동·고마움에도. `딱!`은 사이즈·높이·분위기가 맞았다는 리뷰에. `우와~` `와~` `어머` 같은 감탄사로 여는 것도 OK.
- **마지막 인사는 마지막 문장과 같은 줄에 이어 붙인다**: `오래오래 함께해주세요! 저희 플레르가구를 믿고 구매해주셔서 감사합니다!` → 빈 줄 하나 → 브랜드 블록.
- 뻔한 마무리 문장(`이런 의견이 저희에게 큰 자료예요` 등) 삭제.

**쓰지 말 것 (문어체·번역투)**

| 쓰지 말 것 | 이렇게 |
|---|---|
| 그 수고를 생각하면 마음이 무겁습니다 | 번거롭게 해드려서 죄송해요.. |
| 면목이 없습니다 / 그냥 두기 어렵습니다 | 죄송해요.. / 저희가 더 챙길게요 |
| 감사한 마음으로 읽었습니다 | 감사하게 읽었어요ㅎㅎ |
| ~해야 했다고 생각합니다 | ~했어야 했는데 |
| 그 말씀이 아직도 힘이 돼요 / 많은 분들이 공감하실 것 같아요 | (과하거나 번역투 — 빼거나 짧게) |

### 3-2-1. 제품 핵심 키워드 (반드시 넣는다)
- 답글마다 **그 리뷰의 상품명에서 뽑은 핵심 품목 키워드를 1번 이상** 자연스럽게 넣는다. 검색에 걸리는 품목 이름이다.
  - 예: `블랑누아 세라믹 거실장` → **거실장** / `미네 수납형 소파 테이블` → **소파테이블** / `모던 3단 서랍장` → **서랍장** / `원목 식탁의자` → **식탁의자** / `수납장`, `책상`, `침대 프레임`, `아일랜드 식탁` 등
  - 상품명에 소재·용도가 붙은 품목이 따로 검색되면 그대로 쓴다(`세라믹 거실장`, `원목 식탁`). 단, 소재는 상품명에 있을 때만(3-1 지어내기 금지).
- `제품`, `이 아이`, `요 친구` 같은 말로만 부르지 말고 품목 이름으로 한 번은 부른다. 2번 넘게 반복해 억지로 넣지는 않는다.
- 여러 품목이 함께 있는 상품명(세트)은 고객이 리뷰에서 말한 품목을 고른다.

### 3-3. 답글끼리 똑같아 보이지 않게 (변주 필수)
스마트스토어엔 답글이 줄줄이 보인다. 같은 틀이면 복붙 답글로 보인다.
- **여는 말을 돌려 쓴다**: 감탄사 / 고객 문장 한 구절 받기 / 바로 감사 / 상황 공감. 같은 여는 말이 연달아 나오지 않게.
- **이모지는 사람 표정·사람 손만**: 😊 🥰 😍 ☺️ 🤗 😄 😆 🤭 🙏 👍 🙌 👏. 하트·반짝이·식물·커피 같은 사물/기호 이모지(✨💛🤍🌿☕🩶 등)는 **금지**(AI 같아 보인다). 답글당 0~2개, 위치도 매번 다르게(첫 줄 끝 고정 금지), 이모지 없는 답글도 섞는다.
- **"사진 보니 ~네요"를 매번 같은 자리에 두지 않는다.** `보내주신 사진 속~`, `~놓인 모습이 너무 잘 어울려요` 등으로 바꾸고, 필요 없으면 뺀다.
- **마무리를 돌려 쓴다**: `오래오래 함께해주세요!` `앞으로도 잘 부탁드려요~` `편하게 잘 쓰시길 바랄게요!` `자주 손이 가는 테이블이 되면 좋겠어요~` `편안한 밤 되세요!` `친구분께도 감사 인사 전해주세요!` 등. `오래 편하게 써주세요~` 반복 금지.
- `저희가 다 뿌듯하네요 / 기분 좋네요 / 안심이 되네요` 같은 `저희가 다 ~네요`는 한 배치에 1~2번까지.

### 3-4. 불만·하자·아쉬움 리뷰
- **CS로 넘기지 않는다.** `CS팀에서 연락드리겠습니다` 금지. 답글 안에서 마무리하는 게 최선이다.
- 다 해결해주려 하지 않는다. 교환·회수·부품 발송·검수 강화 같은 조치를 늘어놓지 않는다(필요하면 `저희가 더 챙길게요` 한 줄).
- 사과는 자연스럽게 한 번(`죄송해요..`). 원인을 단정하지 않는다(`초기 불량입니다` 금지).
- 말투는 칭찬 답글과 똑같은 구어체 그대로.
- 흐름: 좋게 봐주신 부분 → 짧은 사과 → 말씀 새겨두겠다 → (가벼운 사진 얘기) → `혹시 계속 불편하시면 편하게 연락 주세요~` → 마지막 인사.
- 관리 팁은 확실한 일반 상식만, 탓하는 느낌 없이(`다음엔 접시 하나 받쳐두시면 걱정 없으실 거예요!`).
- 별점은 낮은데 글은 칭찬뿐이면 칭찬 답글로 쓰고, 문만 살짝 열어둔다. 메모에 적는다.

### 3-5. 응원 메시지
리뷰에 **드러난 상황에만**: 매장·사무실 → 번창 응원 / 이사·신혼 → 새 출발 / 아이 공부방 → 공부 응원 / 선물 → 받으신 분도 오래 편하게 쓰시길.

## 4. 페이지 만들기

`<작업폴더>\body.html`에 카드를 쓴다. 틀은 `templates/card.html`을 Read 해서 그대로 따른다.
- **순서**: 조치 필요(`data-flag`) 카드를 맨 위로, 나머지는 행 순서.
- **메모(`.note`)**: 담당자가 알아야 할 것만 — 반복되는 불만(예: 사이드테이블 색이 생각보다 밝다/노랗다, 조립부 흔들림, 폴딩베드·샤프·포그니 쿠션감, 오프화이트가 회색에 가깝다), 첫 리뷰에 문제가 있던 한 달 후기, 같은 고객 묶음, 별점-내용 불일치, 색이 달라 보이는 사진, 답글에서 일부러 뺀 내용과 그 이유.
- 답글 안에서 `&` `<` `>`는 이스케이프.

조립·검사·저장:
```
powershell -NoProfile -ExecutionPolicy Bypass -File "<스킬폴더>\scripts\build_page.ps1" -WorkDir "<작업폴더>" -Brand 플레르가구 -Source "<엑셀파일명>" -Out "D:\주혁\제품 상세페이지 제작\리뷰답변_YYYYMMDD.html" -ExtraFacts "7|★4 이하 (모두 칭찬)|hot"
```
- 가즈다가구는 `-Brand 가즈다가구`, 파일명 `리뷰답변_가즈다_YYYYMMDD.html`.
- 건수·사진 수·한달사용·조치 필요 수는 스크립트가 카드에서 센다. `-ExtraFacts "숫자|설명[|hot]"`로 상단 요약을 더 붙일 수 있다.
- 검사 항목: 사진 누락, 마지막 인사·하단 블록 형식, 다른 브랜드 정보 섞임, 큰따옴표, `~셨겠어요`류, CS 이관 문구, 문어체, 고객 평가 표현, **사람 표정·손이 아닌 이모지**. 하나라도 `[실패]`면 저장하지 않는다 → 고치고 다시 돌린다. `[경고]`(같은 표현 반복, 같은 여는 말, 줄 수)도 되도록 고친다.

## 5. 올리고 보고하기

- Artifact 로 publish (`file_path` = 저장한 html, 처음이면 `icon: "chat"`, `description` 한 문장). 같은 날 수정이면 같은 경로로 다시 publish → 같은 링크 유지.
- 사용자에게 한국어로 짧게: 링크 → 맨 위로 올린 건(사유) → 참고할 것(반복 이슈, 같은 고객, 색 불일치, 일부러 뺀 표현) → 확인 필요한 것. 표 남발하지 말고 담당자가 바로 이해할 말로.

## 6. 담당자가 고쳐달라고 하면

말투·표현 지적을 받으면 이 SKILL.md 의 해당 규칙(3-2, 3-3 등)에 바로 반영하고, 같은 배치 답글을 다시 써서 같은 경로로 다시 publish 한다.

## 스튜디오 모드 (플레르 MS팀 업무 도구 '리뷰 답글 작성 도우미'에서 호출될 때)
프롬프트에 "스튜디오 모드"가 있으면 업무 도구 사이트가 백그라운드로 실행한 것이다. 사람이 대화를 보고 있지 않다.
- **브랜드·엑셀 경로·작업 폴더·저장 경로는 프롬프트에 있다.** 묻지 않는다(0번 확인 생략).
- 1~4단계(엑셀 풀기 → 사진 전부 보기 → 답글 쓰기 → body.html 카드 + build_page.ps1 검사)는 똑같이 한다. build_page의 `-Out`은 프롬프트의 저장 경로. 검사 `[실패]`면 고쳐서 다시 돌려 통과시킨다(`-Force` 금지). `[경고]`도 되도록 고친다.
- 5단계 Artifact 게시·사용자 보고는 **하지 않는다**.
- 명령은 Bash 도구로 실행한다(`powershell -NoProfile -ExecutionPolicy Bypass -File ...`).
- 끝나면 프롬프트의 `result.json` 경로에 UTF-8로 쓴다:
```json
{
  "page": "<저장한 html 절대경로>",
  "total": 7, "photos": 6, "month": 4, "flagged": 1,
  "notes": ["맨 위로 올린 건과 사유", "반복 이슈·같은 고객·색 불일치·일부러 뺀 표현 등 담당자가 알아야 할 것 (짧게, 최대 6개)"]
}
```
- 엑셀이 리뷰 엑셀이 아니거나 리뷰가 0건이면 `{"error": "<이유>"}`만 쓰고 끝낸다.
