# 네이버 블로그 포스팅 (조회수 나는 주제 + 제품 자연스럽게)

이 스킬은 `plaire-shorts-studio` 플러그인에 들어 있다. 스킬 폴더를 `<스킬>`이라 하면 플러그인 루트는 `<스킬>\..\..`.
- 자료 훑기: `python "<플러그인>\scripts\shorts.py" sheets "<제품폴더>" --out "<작업폴더>\_시트"` → 사진 시트·상세페이지 시트(전부 Read로 본다)
- 사진 편집: `python "<플러그인>\scripts\blog_images.py" crop "<작업폴더>\crops.json" "<작업폴더>\블로그_이미지"`
- 움직이는 이미지: `python "<플러그인>\scripts\blog_images.py" motion "<작업폴더>\motion.json" "<작업폴더>\블로그_이미지"` (GIF 2개 + 16:9 10초 영상)

## 0. 목표

**제품 소개글이 아니라, 사람들이 찾아 읽는 글**을 쓴다. 검색 수요가 큰 주제로 들어와서 → 그 상황에 제품이 자연스럽게 등장한다.
- 예: '사이드테이블'로 쓰지 않고, '천호역 데이트'(검색 많음) → 요즘 OTT 시네마 카페가 인기 → 집에서 영화 볼 때 소파 옆 사이드테이블
- 예: '강남 ○○ 푸르지오'(입주·검색 많음) → 그 단지 평형 거실 크기 → 딱 맞는 거실장 사이즈
- 제품 얘기는 글의 **3분의 1 이하**. 앞부분은 주제 자체로 읽을 가치가 있어야 한다.

### 브랜드별 타깃 (반드시 지킨다)
| | 플레르가구 | 가즈다가구 |
|---|---|---|
| 독자 | **가정집** — 신혼부부, 이사·입주 준비, 아이 있는 집, 홈카페·홈시네마 | **업소** — 카페·식당·사무실·학원·병원 대기실·매장을 운영하거나 꾸미는 사장님·담당자 |
| 들어갈 주제 예 | 신축 아파트 입주, 평형별 거실 배치, 데이트·여가 후 집에서, 계절 집꾸미기 | 창업·개업 준비, 상권·핫플 동향, 인테리어 공사 비용 줄이기, 손님 회전·동선, 업종별 트렌드 |
| 말하는 사람 | **플레르가구(판매자)** — 고객 상담·배송·설치를 하며 가정집을 많이 봐 온 가구 브랜드 | **가즈다가구(판매자)** — 카페·식당·사무실 납품·설치를 많이 해 온 업소용 가구 브랜드 |
| 제품 연결 | 생활 장면(영화, 식사, 아이, 수납) | 운영 장면(좌석 수, 내구성·청소, 단체 주문, 분위기·브랜딩) |
- 가즈다 글에 신혼집·아이 방 같은 가정 얘기를, 플레르 글에 창업·매장 운영 얘기를 넣지 않는다.

### 담당자가 원하는 주제를 적었으면
- 그 주제를 **중심으로** 쓴다. 그 주제 안에서 2단계 조사로 **검색 수요가 큰 표현·키워드**를 골라 제목·본문에 쓴다(예: '신혼집 거실' → '신혼집 거실 인테리어', '24평 신혼집 거실' 중 자동완성에 뜨는 것).
- 주제가 타깃과 어긋나도 담당자 요청을 따르되, 그 브랜드 타깃 독자가 읽을 수 있게 풀어 쓴다.
- 주제가 비어 있으면 아래 2단계대로 직접 고른다.

## 1. 자료 보기

1. sheets로 사진·상세페이지 시트를 만들어 **전부 Read**로 본다. 상세페이지에서 제품명, 핵심 기능, 소재, 사이즈(W×D×H), 컬러를 뽑는다.
2. 제품의 **핵심 키워드**를 정한다(예: 세라믹 거실장, 원목 사이드테이블). 상세페이지 제목·스펙에서 고르고, 사람들이 실제로 검색할 만한 말로.

## 2. 주제·키워드 조사 (WebSearch·WebFetch)

1. 제품이 쓰이는 장면을 **브랜드 타깃에 맞게** 3~5개 떠올린다(플레르: 영화 보는 거실·신혼집 입주·아이 방·손님 초대 / 가즈다: 카페 개업·식당 좌석 배치·사무실 회의실·학원 교실·매장 리뉴얼).
2. 각 장면과 이어지는 **검색 수요 큰 주제**를 찾는다. 요즘 뜨는 것 위주로:
   - 지역·핫플(데이트 코스, 카페, 팝업), 신축 아파트 입주·분양 단지, 계절·명절·연말, 생활 트렌드(홈시네마, 홈카페, 미니멀 인테리어), 평형별 인테리어(24평, 32평)
   - WebSearch로 최근 기사·글을 확인해 **지금** 관심이 큰지 본다(날짜가 오래된 화제는 뺀다).
   - 네이버 자동완성으로 실제 검색어를 확인한다: `curl -s "https://ac.search.naver.com/nx/ac?q=<URL인코딩 검색어>&st=100&r_format=json&r_enc=UTF-8&q_enc=UTF-8"` → 뜨는 연관어가 많고 구체적일수록 수요가 있다고 본다.
3. 후보 주제 3개를 비교해 **하나를 고른다**: 검색 수요(최근성·자동완성) × 제품과 자연스러운 연결 × 경쟁(너무 큰 키워드만은 피하고 '지역/평형/상황 + 품목' 조합 우대).
4. 고른 주제의 **메인 키워드 1개**(주제 쪽, 예: 천호역 데이트)와 **제품 키워드 1개**(예: 소파 사이드테이블), **서브 키워드 3~5개**를 정한다.
5. 근거를 짧게 남긴다(무엇을 확인했는지). **검색량 숫자를 지어내지 않는다** — 확인 못 한 수치는 쓰지 않는다.

## 3. 글 쓰기 규칙

### 길이·구성 (네이버 노출 기준)
- 본문 **1,500~2,200자**(공백 포함) — 길수록 좋은 게 아니다. 사진 **8~12장**.
- 제목: 메인 키워드를 **앞쪽에**, 25~35자. 낚시·과장 금지. 후보 3개를 만들고 가장 좋은 걸 첫 번째로.
- 메인 키워드는 본문에 **4~6번**, 제품 키워드는 **2~4번**, 첫 문단 안에 메인 키워드 1번. 억지로 반복하지 않는다.
- 소제목 3~5개. 소제목은 그냥 한 줄 문장(예: `■ 천호역에서 영화 보고 집에 오면`). `#`, `**`, `-` 같은 마크다운 기호는 쓰지 않는다.
- **표 금지**(네이버에 붙이면 깨짐). 목록이 필요하면 짧은 줄 몇 개로.
- 사진 자리는 본문 사이에 단독 줄로 `[사진 1]` … 처럼 번호를 넣는다(사진 파일 01.jpg… 순서와 같게). 사진 바로 아래 줄에 짧은 사진 설명(선택).
- 움직이는 이미지 자리도 단독 줄로 넣는다: `[GIF 1]`, `[GIF 2]`, `[영상]` 각 1번씩. GIF는 그 장면을 말하는 문단 바로 뒤(컬러 고르기·디테일 설명), 영상은 제품을 처음 제대로 소개하는 곳이나 마무리 직전.
- 한 문단은 2~4줄. 모바일에서 읽기 편하게 문단 사이 빈 줄.
- 마지막에 태그 10~15개(본문과 별도 목록).

### 말하는 사람: 판매자 (반드시 지킨다)
- 글쓴이는 **소비자가 아니라 판매자**(플레르가구·가즈다가구 담당자)다. "제가 샀어요", "우리 집에 들였어요", "저도 티켓팅 실패했어요"처럼 **구매자·사용자 입장의 1인칭 경험담은 쓰지 않는다**.
- 판매자로서 아는 것을 독자에게 알려 주는 시점으로 쓴다: "상담하다 보면 이런 질문을 정말 많이 받아요", "설치 가 보면 이런 거실이 많더라고요", "그래서 저희는 ~하게 만들었어요", "이럴 땐 ~를 먼저 재 보시는 걸 권해요".
- 독자는 '고객님'·'여러분'처럼 2인칭으로 부르고, 자기 쪽은 '저희'·'저희 플레르가구(가즈다가구)'로 부른다.
- 상담·설치 이야기는 **일반적인 장면**으로만 쓴다. 특정 고객 이름·주소·숫자를 지어내거나 "지난주 ○○아파트 고객님이…" 같은 지어낸 사례는 쓰지 않는다.

### 말투 (AI 티 안 나게)
- 판매자가 고객에게 편하게 이야기하듯 쓰는 구어체: `~해요`, `~더라고요`, `~거든요`, `~잖아요`. 문장 길이를 섞는다. 딱딱한 회사 공지·보도자료 말투는 쓰지 않는다.
- 구체적인 장면·감각·작은 디테일로 쓴다(퇴근 후 시간, 조명, 팝콘, 리모컨 둘 곳 등). 일반론·설명문 금지.
- **쓰지 말 것**: `~에 대해 알아보겠습니다`, `결론적으로`, `오늘은 ~를 소개해드리려고 합니다`, `다양한`, `완벽한`, `최고의`, `혁신적인`, `~할 수 있습니다`로 끝나는 설명체, 매 문단 같은 구조, 느낌표 남발, 이모지 남발(0~3개), 영어 섞기, 마무리 요약 목록.
- 광고 냄새 줄이기: 가격·할인·구매 유도 문구("지금 구매하세요", "한정 특가")는 쓰지 않는다. 제품은 "저희가 이런 고민 때문에 이렇게 만들었어요"처럼 만든 이유·쓰임으로 소개하고, 브랜드명은 '저희'로 대신하며 정식 이름 '플레르가구'(또는 '가즈다가구')는 2~3번만.

### 사실
- 제품 사양(소재·사이즈·기능·컬러)은 **상세페이지에 있는 것만**. 없는 기능·수치·인증을 만들지 않는다.
- 주제 쪽 정보(장소·단지·트렌드)는 **확인한 것만**. 영업시간·가격·평형 같은 수치는 확인 못 했으면 쓰지 않거나 두루뭉술하게.
- "몇 달 써보니 흠집 없어요" 같은 **지어낸 사용 결과**·고객 후기는 쓰지 않는다. 장점은 상세페이지에 있는 소재·구조로 설명한다.
- 아파트 평형 추천은 일반적인 거실 폭 기준으로 말하고, 특정 단지 실측을 단정하지 않는다.

## 4. 사진 편집 (3:2)

1. 제품 사진 시트를 보고 글 흐름에 맞는 사진 **8~12장**을 고른다. 사람이 크게 나온 사진·흐린 사진·같은 구도 반복은 뺀다. 상세페이지 이미지(글씨 많은 것)는 쓰지 않는다.
2. `<작업폴더>\crops.json`을 쓴다(순서 = 본문 [사진 N] 순서):
```json
[{"file": "<원본 절대경로>", "cx": 0.5, "cy": 0.55, "zoom": 1.0}]
```
   - cx·cy: 남길 중심(0~1, 가로·세로 비율), zoom: 1.0=가능한 가장 넓게, 1.3=조금 당겨서. 제품이 잘리지 않게.
3. `blog_images.py crop` 실행 → `블로그_이미지\01.jpg…`(1500×1000) + `블로그_이미지.zip` + `_검수.jpg`(전체 모아보기). `_검수.jpg`를 Read로 보고 잘린 곳이 있으면 고쳐서 다시 돌린다.

## 4-2. 움직이는 이미지 (GIF 2개 + 16:9 10초 영상)

블로그 체류 시간을 늘리려고 사진과 함께 **움직이는 이미지 3개**를 꼭 만든다. 새로 생성하지 않고 고른 제품 사진을 움직여 만든다(AI 생성 없음).
1. `<작업폴더>\motion.json`을 쓴다:
```json
{
  "gifs": [
    {"kind": "fade", "shots": [{"file": "<원본>", "cx": 0.5, "cy": 0.5}, {"file": "<원본>"}, {"file": "<원본>"}]},
    {"kind": "zoom", "shots": [{"file": "<원본>", "cx": 0.5, "cy": 0.45}], "to": 1.8}
  ],
  "video": {"shots": [{"file": "<원본>"}, {"file": "<원본>"}, {"file": "<원본>"}, {"file": "<원본>", "cy": 0.6}],
            "title": "<제품명>", "brand": "<PLAIRE 플레르가구 | GAZDA 가즈다가구>"}
}
```
   - GIF 1 (`fade`): **같은 구도의 다른 컬러** 3~4장이 가장 좋다(없으면 다른 각도·공간 컷). 사진이 천천히 넘어가며 반복된다.
   - GIF 2 (`zoom`): 소재·마감·기능이 잘 보이는 사진 1장, `cx`·`cy` = 당겨 들어갈 디테일 위치, `to` = 당기는 배율(1.5~2.0).
   - 영상: **가로 사진 우선** 3~5장(공간 전체 → 사용 장면 → 라인업·디테일 → 마무리 컷 순). 끝 3초에 제품명·브랜드가 아래에 뜬다. 소리 없음.
   - 사람이 크게 나온 사진·상세페이지 이미지(글씨 많은 것)는 쓰지 않는다. 블로그 사진과 겹쳐도 된다.
2. `blog_images.py motion` 실행 → `블로그_이미지\움직임_1.gif`, `움직임_2.gif`(800×533), `영상_16x9.mp4`(1920×1080, 10초)가 생기고 사진 zip에도 들어간다. `_움직임_검수.jpg`를 Read로 보고 제품이 잘리거나 엉뚱한 곳을 당겼으면 고쳐서 다시 돌린다.

## 5. 결과 (스튜디오 모드)

프롬프트에 "스튜디오 모드"가 있으면 업무 도구가 백그라운드로 실행한 것이다. 질문하지 않는다. 끝나면 프롬프트의 `result.json` 경로에 UTF-8로 쓴다:
```json
{
  "title": "<제목 1순위>",
  "title_options": ["<후보2>", "<후보3>"],
```
